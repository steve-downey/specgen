# Plan: wording diffs against a baseline

**Status:** ACCEPTED, 2026-11-05; every open question was settled with the user the same day and the
answer is recorded in place under its slug. PR 1 (steps 1–3) is #241; PR 2 (steps 4–5) is #246; PR 3
(step 6, `--baseline-rev`) follows it on this branch. Design §7 reserved the seam
("the seam for future IR-level diff markup (add/rm wording generated from two header revisions;
out of scope, by hand at first)"), and `--paper` is the by-hand first cut: it marks a whole fragment
as added. This plan replaces that with a diff, and makes `--paper` the special case of it.

No issue yet; this document is the proposal. The questions at the end were the taste calls the user
owns; each records the recommendation it was asked with and the decision.

## Why

A paper that modifies an existing facility proposes an *edit*, not a clause: "Modify
[optional.ctor] as indicated", removed text struck through, added text underlined, and reviewers
read the delta. The draft PR for the same change is the new wording, plain, spliced over the old.
specgen produces the second and nothing toward the first. `--paper` says "all of this is added",
which is true of a fragment specifying a new facility and false of a changed one, and a paper
revising its own wording (R1 against R0) has the same problem one step removed.

The acid test (docs/acid-test.md) already reverse-engineers [optional] into a Beman-style header
whose generated LaTeX matches the frozen draft. The step after that is to edit the header and get
the paper's diff out of the edit, while the draft PR remains the plain render of the same header.
One source, two outputs, and the two cannot disagree because the second is the first with the
marks stripped.

## Which level to diff at

Three candidates:

1. **Rendered text**, as `latexdiff` or an HTML differ would. Backend-specific and markup-blind: a
   token diff over LaTeX splits `\tcode{...}` and `@\exposid{...}@` escapes, a paragraph inserted
   near the top renumbers everything under it, `latexdiff` is known to produce unbuildable output
   inside `listings` environments, and three backends means three differs, or one that knows all
   three syntaxes.
2. **Header source**, git's own diff projected into wording. Source edits do not map one to one: a
   docblock reorder is no wording change, a `static_assert` edit moves a derived *Mandates*
   paragraph and a drift warning in different places, and a clang-format run changes nothing at
   all.
3. **The IR.** It is the wording ontology (§7), Clang-free (decision clang-free-render-mode),
   serializable, produced for every document anyway, and tree-shaped, so matching can be
   structural where structure exists (sections by stable name, items by what they declare,
   elements by kind) and sequence-based only where the content is a sequence (paragraphs, words,
   code lines). The marks are then one more thing each backend renders through the algebra it
   already has, in all three (§12's one-convention-three-writers rule).

Level 3, which is the one §7 reserved. It has a property the other two lack: the diff of an
*empty* baseline against a document is exactly today's `--paper` output, so paper mode becomes a
case of the diff rather than a sibling of it, and `golden.paper_mode` / `golden.paper_mode_org`
not moving is the regression invariant for the whole change.

## Design

### The baseline

A baseline is one `ir::Document` per document of the paper, paired with the documents in order
the way `--root` pairs. Three ways to supply one, in the order they should land:

- **`--baseline-ir <file>`**, on both `generate` and `render`: a saved IR, the output of an earlier
  `--emit-ir`. This is the form a paper commits: `papers/wording/R0.json` beside the fragments
  makes R1's diff reproducible without the pinned LLVM, the same argument the user guide makes for
  committing fragments, and it is the only form that can name a baseline whose headers were
  generated by a build (`.build/generated/include`) and are not in any revision.
- **`--baseline-header <path>`**, on `generate`: the old header checked out somewhere, parsed with
  the same compile arguments. It is what `--baseline-rev` reduces to, and it is the golden
  harness's path: the corpus is hermetic (decision hermetic-corpus), so a generate-mode diff golden
  names two corpus headers and never runs git.
- **`--baseline-rev <rev>`**, on `generate`: a git revision. One flag for the whole paper: each
  header's own path at that revision is that document's baseline, and a header the revision does
  not have gets the empty baseline, so the document renders as all added, with a note on stderr
  saying so. A document is "the main file and the includes inside its `.syn` region" (decision
  document-extent) and `\expos` reaches included headers (issue #36), so the baseline's includes
  must be the baseline's: the revision is materialized as a tree, not a file.

Materializing the revision is git plumbing against a temporary index, which touches neither the
real index nor the worktree list and needs no `tar`:

```sh
GIT_INDEX_FILE=$scratch/index git read-tree $rev
GIT_INDEX_FILE=$scratch/index git --work-tree=$scratch/tree checkout-index -a
```

The header path and every compile argument path under the repository's top level (`-I include`, an
`-isystem`, the `--compile-commands` directory) are remapped under `$scratch/tree`; paths outside
the repository are left alone. A subprocess rather than libgit2 because specgen is a tool
(decision tool-not-library) whose release binary is static (decision portable-release-binary), and
`git` is on the PATH of every build that would pass a revision. The scratch tree lives for the
run.

A baseline IR and a `--baseline-header`'s parse sources are prerequisites in the `--depfile` sense
and are listed; a revision's files are not on disk after the run and are not, so a build that
passes `--baseline-rev` owns the rebuild rule for it, as it owns the revision.

### The diff

A new Tier-A component, `diff`, with one entry point:

```cpp
ir::Document diff::compare(const ir::Document& baseline, const ir::Document& current,
                           const diff::Options&);
```

Both inputs canonical. The result is `current` with change marks (next section) and, under the
default context, with the unchanged top-level sections removed. Matching proceeds by level, and
each level uses structure before it uses a sequence algorithm:

- **Nodes.** Among siblings, a `Section` matches the `Section` with the same stable name, a
  `Synopsis` the `Synopsis` with the same `name`, a `SpecItem` the `SpecItem` whose `entities` and
  signature texts are identical. Leftover items in one parent that share an entity set pair in
  order: an overload set whose signature changed (a `noexcept` added, a constraint tightened) is
  the same item with a code change, not a removal and an addition. `FreeParagraph`s pair as
  paragraphs do below. What is left after that is added or removed, placed by a longest-common-
  subsequence over the sibling keys, so a node that *moved* is a removal and an addition, which is
  honest and what git does. Order is the current document's.
- **Elements** of a matched item match by `ElementKind`, the k-th of a kind to the k-th
  (`canonicalize` is a stable sort, so two elements of one kind keep authored order). An unmatched
  element is added or removed whole.
- **Paragraphs** of a matched element, and the items of an `Itemize`, pair by LCS over paragraphs,
  two paragraphs being pairable when their word sets agree past a threshold
  ([paired-paragraph-threshold](#paired-paragraph-threshold)); an unpairable one is added or
  removed whole. Within a pair the diff is over tokens: a `TextInline` splits at whitespace into
  words, each carrying the whitespace after it, which is what `wdiff` and `git diff --word-diff`
  do; a `CodeInline`, `RefInline` or `ConceptRef` is one token. A `\tcode{...}` is therefore
  atomic: the diff never marks half of one. Table rows pair by their heading cell (`Table2D`) or
  first cell (`Table1D`), and the cells then pair as paragraphs.
- **Code** (a synopsis, a signature, an *Equivalent to* body) diffs by line first. A removed line
  adjacent to an added one, or a pair past the same similarity threshold, diffs again inside the
  line over C++-ish tokens: identifiers, numbers and punctuation each one token, whitespace
  attached to the token before it, and *a semantic span is one token*, so the span table's
  invariant (sorted, non-overlapping) survives: a change run contains whole spans or none of one.
  A run never crosses a line end, because the LaTeX rendering below cannot.

The sequence algorithm is Myers' greedy O((N + M)·D) edit script, the one git uses by default, written
once over any random-access range with an equality predicate (`diff/sequence.hpp`, header-only,
no Clang, a hundred lines). "Minimal" is its guarantee for the tokens it is handed; the structural
matching above is what keeps the result readable, by never handing it a removed paragraph's words
beside an unrelated added paragraph's to pair up. After the script, git's cleanup heuristic: an
unchanged island shorter than a few tokens between two changes joins the change, because
`[a]{.rm}[b]{.add} x [c]{.rm}[d]{.add}` reads worse than one replaced phrase
([cleanup-island-size](#cleanup-island-size)).

Three laws, pinned by unit tests over hand-built IR:

- identity: `compare(d, d)` carries no marks and equals `d` under `all` context;
- empty baseline: `compare({}, d)` marks every top-level node Added and nothing beneath;
- restoration: stripping the Removed material and the marks from `compare(a, b)` gives `b`, and
  stripping the Added material gives `a`, up to runs of whitespace. A mark spans the changed
  tokens and leaves the whitespace around them outside, as hand-written diffs do
  (`\added{constexpr} R`, issue #258), so a word added between two others leaves the baseline
  side two separators where it had one. A removal directly followed by an addition abuts it,
  `[a]{.rm}[b]{.add}`, the removal's trailing whitespace dropped.

### Marks in the IR

Two ways to carry the result. A separate diff tree with its own node vocabulary would need a
second render algebra in every backend; rejected. The marks go into `ir` itself: a `::: add` div
is an editing instruction, semantic to the paper, not typography, so §7's "no typography" rule
is not touched.

- `enum class Change { Same, Added, Removed }`, with its `foundation::enumerators` list beside
  it (the `no-raw-switch` rule).
- A `change` field on `Section`, `Synopsis`, `SpecItem`, `FreeParagraph` and
  `DescriptionElement`, `Same` by default. A mark on a node covers everything beneath it, and
  descendants of a marked node carry `Same`, so nothing is marked twice.
- Prose: `Inline` gains a fifth alternative, `ChangedInline { Change change; std::vector<Inline>
  inlines; }`, the recursive-variant shape, so one mark covers a run of inlines and a backend
  writes one `[...]{.add}` per run rather than one per word. Every `Inline` visitor is already a
  named struct (decision visitation-rules, four alternatives), so the fifth is a compile error at
  each of them, which is the tripwire doing its job.
- Code: `CodeText` gains `std::vector<ChangeRun> changes` (byte range plus `Change`), sorted and
  non-overlapping, a second table beside `spans` rather than new `SpanKind`s, because a change run
  *contains* spans and spans do not nest.
- JSON: one key per field, omitted at the default so every checked-in golden parses and
  re-emits unchanged; `"t": "changed"` for the inline; `"changes"` on code. The format grows
  additively, as it did for `entities`.

The validator channels of the result are the current document's. Validation runs over the
current document before the diff, never over the baseline, whose findings belonged to the run
that produced it.

### Rendering

Each backend spells the marks in its own convention. The spellings below are the frameworks'
own, not inventions:

| mark | mpark/wg21 | draft LaTeX (`macros.tex`) | org (wg21org) |
| --- | --- | --- | --- |
| node added | `::: add` div | `addedblock` | `addedblock`; `:WG21_CHANGE: add` on a section |
| node removed | `::: rm` div | `removedblock` | `removedblock`; `:WG21_CHANGE: rm` on a section |
| prose run | `[...]{.add}`, `[...]{.rm}` | `\added{...}`, `\removed{...}` | `[[insert:][...]]`, `[[delete:][...]]` |
| code run | `@[...]{.add}@`, `@[...]{.rm}@` | `@\added{...}@`, `@\removed{...}@` | the LaTeX bytes |

The org forms are specgen's to choose and wg21org's to support, within what org can express
([org-forms](#org-forms)). The LaTeX macros are the draft's own
(`\added`, `\removed`, `addedblock`, `removedblock` in `source/macros.tex`), which is what makes a
LaTeX paper diff and the draft PR the same vocabulary; and since the org special blocks export to
the draft's `lstnewenvironment`s, the code-run bytes are shared with LaTeX exactly as
`draft_spans.hpp` already shares the span bytes.

The code run has a subtlety that is already solved once. Inside a `@...@` escape the text is TeX,
so a semantic span inside a changed run renders through `draft_span_prose` (`\exposid{x}`), not
`draft_span_codeblock` (`@\exposid{x}@`), which would close the escape early; mpark's `$x$`
shorthand likewise becomes the `*x*` it abbreviates inside an open `@...@`. `render_code_spans`
grows the second table and tells `escape_span` whether a change is open. A run never crosses a
line end because a `listings` escape is line-local; a wholly added line is one run.

Paragraph numbers: an added paragraph takes the `x`, `x+1` literal run `--paper` already emits,
and a retained or removed one keeps `#`. mpark's filter leaves its counter alone at a literal and
wg21org's `pnum` does the same, so a modified subclause numbers 1, 2, x, 3, with the existing
paragraphs keeping the numbers the draft gives them, provided the fragment starts at the
subclause's first paragraph, which it does when the baseline covers the subclause. The draft's
`\pnum` has no literal form; inside `addedblock` it numbers on, which is all the draft's macros
offer.

What to emit for unchanged material is `--diff-context`, four levels, all supported: `changed`
(the default) drops a top-level node with no change anywhere in it and renders a changed one
whole, unchanged paragraphs included; `all` renders everything, for the paper that has to *show*
nothing else changed; and `items` goes one step further than `changed`, collapsing each maximal
run of unchanged children inside a changed section to one ellipsis paragraph, because LWG would
rather not page through wording that did not move
([diff-context-default](#diff-context-default), [diff-context-items](#diff-context-items)). The
ellipsis is an unnumbered paragraph reading `[…]` in mpark and org and `[\ldots]` in LaTeX, the
form papers write by hand; a first cut, signed off on the golden. A changed item still renders
whole under `items`: the unit of elision is a node, not a paragraph. `decls`
applies the same section elision and also replaces an unchanged, nonempty description
of a retained item with one unnumbered ellipsis (issue #264). A changed description
stays whole, and added or removed items stay whole. An unchanged subsection
keeps its own heading over one ellipsis for its wording, and so does each subsection nested in
it, at any depth (issue #263). A `\ref` to it from retained wording then still resolves, the reader sees which
subclause was left out, and the next sibling's number comes from that level's counter as in the
draft. Where two elisions would render one after the other -- a changed subsection ending in
elided children, then an unchanged run of its parent's paragraphs -- they are one ellipsis
(issue #259); between two subsections a heading always separates them. The editing instruction sentence
("Modify [gadget.observe] as indicated:") stays the paper's, as it is under `--paper` today
([editing-instructions](#editing-instructions)).

`fragments::split` does not change: a fragment of a marked document is a marked document, and a
dropped section is dropped before the split, so the manifest lists only what changed. The
whole/pieces invariant (`golden.paper_whole.is_fragments`) holds as it stands.

### Paper mode is the empty baseline

`--paper` with no baseline becomes `compare({}, d)` rendered, and the three backends' paper-mode
wrappers (`wrap_added`, `renumber_added`, `number_added_pnums` and the `:WG21_CHANGE: add`
branch) go away in favour of the mark renderers; `golden.paper_mode` and `golden.paper_mode_org`
pin that not a byte moved. A baseline flag implies `--paper`, since a diff has no unmarked
rendering ([paper-implies-diff](#paper-implies-diff)). The LaTeX backend, which refuses
`--paper` today for want of anything to say, accepts it once `addedblock` is what it says
([latex-paper-mode](#latex-paper-mode)). The draft PR is unchanged by all of this: no `--paper`,
no baseline, the plain render as today.

`--emit-ir` with a baseline emits the marked document, so `render --from-ir diff.json` renders it
with no baseline, which is how render-mode goldens and a committed diff IR work. A marked document
given to `render` *beside* a baseline is refused: diffing a diff means nothing.

### Where it lives

- **Sequence diff** — `include/beman/specgen/diff/sequence.hpp`, header-only, Tier A.
- **Diff** — `include/beman/specgen/diff.hpp`, `src/beman/specgen/diff.cpp`: the prose and code
  tokenizers, the structural matcher, `compare`, `Options` (context, thresholds).
- **IR** — `Change`, the five fields, `ChangedInline`, `ChangeRun`; **IR serialization** — their
  descriptors.
- **Backend substrate** — `code_spans.hpp` walks two tables; `draft_spans.hpp` gains the change
  spellings; **the three backends** render every mark.
- **Baseline tree** — `include/beman/specgen/baseline_tree.hpp`, `src/beman/specgen/baseline_tree.cpp`,
  Tier A (clang-free; the parse of the remapped header is the front end's): materialize a revision,
  remap the header path and compile arguments, report a header missing at the revision.
- **Driver** — the three baseline flags, `--diff-context`, the pairing, the refusals; `compare`
  called in `emit_wording`/`emit_paper` after validation and before rendering, so `generate` and
  `render` agree byte for byte as they do for everything else.

## Open questions

Slug-headed so the record can graduate in place. Each kept the recommendation it was asked with,
and records the decision; all were settled on 2026-11-05.

### baseline-spelling

**Question.** Three flags, or one `--baseline <spec>` with a scheme (`rev:HEAD~3`, `ir:R0.json`)?
**Status.** DECIDED: three flags.
**Recommendation.** Three flags. No scheme parsing, and each flag's usage error can say which
command takes it (`--baseline-rev` is `generate`'s alone).

### paper-implies-diff

**Question.** Does a baseline flag imply `--paper`, or must both be written?
**Status.** DECIDED: a baseline implies `--paper`.
**Recommendation.** Imply it. A diff's only rendering is the marked one, and `--paper` alone keeps
meaning what it means now: the empty baseline.

### latex-paper-mode

**Question.** Accept `--paper` on the LaTeX backend?
**Status.** DECIDED: accepted.
**Recommendation.** Yes, once it means `addedblock` around the fragment. The refusal existed
because there was nothing to emit; the draft's own macros are the thing to emit.

### diff-context-default

**Question.** `changed` or `all` by default?
**Status.** DECIDED: `changed` is the default and `all` is supported alongside it; see
[diff-context-items](#diff-context-items) for the third level.
**Recommendation.** `changed`. A paper modifying one subclause of [optional] should not get
[optional] back.

### diff-context-items

**Question.** A third level that elides unchanged *items* inside a changed section, with an
ellipsis paragraph between the survivors?
**Status.** DECIDED: in PR 2, as `--diff-context items`, alongside `changed` and `all`.
**Recommendation.** The recommendation was to wait for a paper that needs it, since neither mpark
nor the draft macros have an elision form. The user's answer: LWG prefers not to skip through
unchanged wording, and it is also sometimes necessary to show that nothing changed, so both ends
are needed. The ellipsis form is specgen's own convention, written the way papers write it by
hand; see the rendering section.

### paired-paragraph-threshold

**Question.** When are two paragraphs the same paragraph edited, rather than one removed and one
added?
**Status.** DECIDED: half, as the first cut.
**Recommendation.** Half their words in common (Jaccard on the word sets), first cut, tuned on the
corpus pair's goldens and signed off on the wording.

### cleanup-island-size

**Question.** How short an unchanged run between two changes joins them?
**Status.** DECIDED: two, as a constant.
**Recommendation.** Two words, or two code tokens, as a constant; an option only if a paper wants
otherwise. Same sign-off as above.

### editing-instructions

**Question.** Emit "Modify [stable.name] as indicated:" before a changed section, or leave the
instruction to the paper?
**Status.** DECIDED: the paper's.
**Recommendation.** Leave it to the paper in this plan, as `--paper` does. The sentence depends on
whether the section is new, changed, or the paper's own revision, and on the paper's house style.
Revisit once the marks exist.

### org-forms

**Question.** Which org spellings carry the marks?
**Status.** DECIDED: the spellings below, and the macro for a cross-reference inside a marked run.
wg21org is ours and will support what works best here, within org's constraints; what the
exporters lack is theirs to add.
**Recommendation.** Mirror the forms that exist. A removed section carries `:WG21_CHANGE: rm`
beside the `add` the backend already writes; a removed node outside a section sits in a
`removedblock` special block beside `addedblock`, which org's stock LaTeX export already turns
into the draft's `\begin{removedblock}` and the HTML exporter styles like its twin. A prose run
is an `[[insert:][...]]` or `[[delete:][...]]` link, the forms `AUTHORING.md` documents. A code
run is `@\added{...}@` or `@\removed{...}@` inside the special block, which `wg21-wording.el`
recognizes today, and the bytes are the LaTeX backend's.

The one constraint org imposes is that links do not nest: a link description cannot hold another
link, and a changed run routinely holds a cross-reference (`see [x]` is a common edit), which the
org backend renders as a real org link. Two ways out, both wg21org's to settle. A reference
inside a marked run can be spelled as a macro (`{{{sref(stable.name)}}}`), which org does allow in
a description and the exporter expands to the same target the link resolves to; or a marked run
can leave links entirely for the paired export snippets the backend already uses for a spanned
code inline (`@@latex:\added{@@ ... @@latex:}@@` with its `@@html:<ins>@@` twin), which contain
nothing and so nest around anything. The macro keeps the mark a single object the exporter can
see, and the fallback is only needed inside a run; recommend the macro, with the snippet pair
held in reserve for whatever else turns out not to fit in a description.

### git-materialization

**Question.** `read-tree` into a temporary index plus `checkout-index`, `git archive | tar`, or
`git worktree add --detach`?
**Status.** DECIDED: the temporary index.
**Recommendation.** The temporary index. `archive` needs `tar`; a worktree is registered state
that a crash leaves behind for `git worktree prune`; `git --work-tree=... checkout <rev> -- .`
rewrites the real index. The plumbing pair touches nothing of the user's.

### version-bump-level

**Question.** Patch or minor, per PR?
**Status.** DECIDED: minor for each feature PR.
**Recommendation.** Minor for each feature PR below. This plan's own commit is a patch.

## Steps

Three PRs, each green (full ctest, `make lint`, goldens and captures in the same commit), in
this order; the first is useful on its own, since a hand-marked IR then renders in all three
backends, which is the by-hand route §7 described.

**PR 1 — marks and their rendering.**

- **Step 1.** `diff/sequence.hpp`: Myers over random-access ranges, the cleanup pass. Catch2: identity,
   all-insert, all-delete, small cases against a brute-force LCS (script length equals
   n + m − 2·LCS), and that applying the script to `a` yields `b`.
- **Step 2.** IR: `Change`, the fields, `ChangedInline`, `ChangeRun`; JSON round trip with the keys omitted at
   the default. Every existing golden unchanged, which is the acceptance test.
- **Step 3.** Backends: every mark in all three; `code_spans.hpp`'s second table; `draft_spans.hpp`'s change
   spellings; the prose-form rule inside an open code run. A render-mode golden from a
   hand-written marked IR (`tests/golden/diff_marks/input.json`, one expected file per backend)
   covering an added and a removed section, item, element and paragraph; a prose run holding a
   code inline; a code run holding an exposid span; a run on a line with a `\ref` comment; an
   added paragraph between two retained ones. LaTeX accepts `--paper`. Paper mode re-routed
   through the marks, the three wrappers deleted, `golden.paper_mode*` byte-identical.

**PR 2 — the differ and the command line.**

- **Step 4.** `diff.hpp`: tokenizers, matcher, `compare`, `Options`. Unit tests over hand-built IR: the three
   laws; a changed-signature overload pairs; a renamed section is removal plus addition; reordered
   items; a word-level paragraph edit; a code inline and a span stay atomic; the threshold and
   island constants at their boundaries.
- **Step 5.** Driver: `--baseline-ir` (both commands), `--baseline-header` (`generate`),
   `--diff-context` with all three levels and the ellipsis paragraph in each backend, the pairing,
   `--emit-ir` with a baseline, the refusals. Golden `MODE=diff` in two forms:
   generate (`INPUT` plus `BASELINE` corpus headers) and render (`INPUT` plus `BASELINE_IR`),
   each with a `.singlepass` sibling (generate with the header pair equals render with the IR
   pair) and a `.selfdiff` sibling (baseline equal to input renders as the plain render under
   `all`). Corpus pair `tests/corpus/diff/gadget.before.hpp` and `gadget.after.hpp`: a renamed
   member, an added overload, a removed one, a changed constraint (derived wording moving), a
   reworded *Returns*, an untouched item inside a changed section, an untouched section. Both
   also registered as ordinary generate goldens; the diff golden renders at each context level.
   An `examples/cli/` script and capture; a section in `docs/examples.org`.

**PR 3 — the revision.**

- **Step 6.** `baseline_tree` (at the top level, not under `frontend/`: it is clang-free string
   and subprocess work, Tier A, and the parse of the remapped header is the front end's as for any
   header): the plumbing pair, the scratch lifetime, the path remap, the missing-at-revision note.
   Unit test against a throwaway `git init` repository. No golden: the harness never runs git
   (decision hermetic-corpus). No example either: CI's checkout is shallow, so a fixed revision of
   this repository's own corpus is not reliably in the clone the examples re-run from.

**Each PR.**

- **Step 7.** Docs: `docs/architecture.md` §2 (the options), §7 (the marks, replacing the "out of scope"
   sentence), §8 (the per-backend table, `--paper` on LaTeX), §10 (the diff mode and its
   siblings), §11 (the components); `docs/user-guide.md`, a "Diffing against a baseline" section
   and the one-source workflow: the paper diff from the baseline, the draft PR from the plain
   render; a decision record `docs/decisions/ir-level-diff.md` and its README row, in PR 1; the
   four version files.

## Out of scope

- **Splicing** the plain render into the draft's `source/*.tex` over a stable-name range: the
  other half of "the PR from the same sources". Today the acid test does it by hand with line
  ranges. A follow-up command once the ranges have a name; nothing in this plan depends on it.
- **Moves and renames.** A section whose stable name changed, or an item that moved between
  sections, is a removal and an addition.
- **Cross-document** matching: a section that moved from one header of a paper to another.
- **Comparison tables** (`::: cmptable` before/after). A different presentation of the same marks;
  possible later from them.
- **Diffing the derived against the authored** is the drift validator's job and stays there.
